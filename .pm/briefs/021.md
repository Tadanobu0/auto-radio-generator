# 画像段で 1 場面あたり N 枚の候補を作り、一覧画像を出す(選ぶのは Mac 側)

## 背景
- 今の画像の検品は、`run_workflow_sync(images_only=True)` で 1 場面 1 枚を作り、Mac 側(radio_director)が画像を見て、外れた場面だけ `regen_scenes` + seed ずらしで作り直す往復(ブリーフ 016・018・023)。1 枚ずつでは「運が悪いのか、プロンプトが悪いのか」が分からず、3 回目で許容に落ちることがある。
- PM の方針(2026-11-04): 1 場面につき候補を一気に N 枚(既定の想定は 9)作り、Mac 側が一覧画像を見て 1 枚選ぶ。選べない場面はプロンプトを書き換えて、その場面だけ N 枚作り直す。サムネイル背景も同じ扱い。

## やること(ARG 側)
1. `images_only=True` のときに **候補数 N を受ける**(引数名は実装に任せる。例 `candidates`)。既定は 1 で、**今までの動き・出力の形は変えない**。
2. N ≥ 2 のとき、各場面を seed 違いで N 枚作る(seed の決め方は既存の regen_seed_offset の流儀に合わせる)。保存は `scene_images/` に候補番号付きで(例 `NN_<segment_id>_c1.png` … `_cN.png`)。`scene_images.json` と `result.json` の `scene_images` に候補の一覧(番号・パス・seed)を足す(既存のキーは残す)。
3. 場面ごとに **一覧画像(コンタクトシート)** を 1 枚作る(N=9 なら 3×3。一般には ceil(sqrt(N)) 列)。各タイルに候補番号を大きく描く。Mac 側はこの 1 枚だけを見て選ぶので、1 タイルが小さすぎないよう 1 枚の長辺 2048px 程度を目安に。パスも `scene_images.json` に載せる。
4. サムネイル背景(ブリーフ 018 の `thumbnail_bg.png`)も N 枚 + 一覧画像を作る(`thumbnail_background_mode: dynamic` のときだけ、という条件は変えない)。
5. **選んだ候補を本番に渡す入口**: `reuse_images_from` と一緒に「場面 → 候補番号」の指定を受ける(例: run ディレクトリに `picks.json` を置く、または引数で `segment_id=番号,…,thumbnail=番号`。どちらか 1 つに決めて、理由を DECISIONS に)。指定が無い場面は候補 1(= 今までどおり)を使う。
6. **プロンプトの差し替えの入口**: `regen_scenes` と一緒に、場面ごとのプロンプト(scene_visual 相当の文)の上書きを受ける(例: `prompt_overrides.json`: segment_id → 文)。上書きされた場面はその文から画像を作り、`scene_images.json` に上書きした旨と文を記録する。verified_script.json 自体は書き換えない。
7. 1 枚あたりの生成時間を `result.json`(場面ごと・候補ごと)に記録する。まだ 4070 での実測が無く、N を 9 にするか 4 にするかはこの値で PM が決めるため。
8. テストは追加のみ(Append-Only)。実機の ComfyUI・GPU は使わない(モック)。既存テストは変えない。

## 守ること
- 既定(N=1、picks なし、overrides なし)の挙動と出力は今までと同じにする。Mac 側の `run_remote.py`(radio_director)はこのジョブでは触らない。Mac 側が渡す必要がある引数・ファイルの形は、報告の「未解決点」に Mac 側向けの箇条書きで書く(次のジョブで radio_director 側を直す)。
- `.env`・認証情報・user_settings の値は読まない。
