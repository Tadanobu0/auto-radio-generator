# ラジオ動画の画像段を B70(ComfyUI)へ移すための調査(変更はしない)

## 目的
ラジオ動画(radio_director → ARG)の画像段は、今は Windows 機の ARG が 4070 の Forge を呼んで作っている。動画の書き出しはすでに Mac(arg-render)で行っている。この画像段を、Windows 機を使わずに B70 機の ComfyUI で作れるようにしたい。今回は調べて案を出すところまでで、コードは変えない。

背景:
- B70 の ComfyUI は http://192.168.0.70:8188(GPU0 で常駐、認証なし)。4070 と同じ条件(flux1-schnell-fp8 / 1344x768 / steps 4 / CFG 1 / Euler / Simple)のワークフローが ~/projects/b70-box/comfyui/workflows/flux1-schnell-fp8.api.json にあり、見た目は 4070 と同じ程度、速さは 3.7 倍以上と確認済み(b70-box の docs/comfyui-flux-bench.md)
- forge-remote の forge-gen は、別のジョブ(forge-remote-006)で B70 の ComfyUI へ切り替え中
- Windows 機が家族の使用中だと画像段が始められない(radio_director の終了コード 20)ことが何度もあった。移せばこれも解消する

## 調べること
1. ARG の画像段が Forge をどう呼んでいるか: API(txt2img か、ほかに img2img・hires fix などを使っているか)、渡している条件(サイズ・steps・sampler・ネガティブ・seed の振り方)、サムネイル背景のサイズや条件が場面画像と違うか
2. 画像段の機能: 候補(candidates)・一覧画像(contact_sheet)・作り直し(regen_scenes・regen_seed_offset)・prompt_overrides・reuse_images_from・キャッシュ(cached)・ロゴの検品などが、Forge の API のどこに依存しているか
3. Windows 機に依存している部分: 起こし方・使用中の判定(終了コード 20)・パスの書き方(E:\...)・Forge の起動と停止・forge-down --if-idle との関係。radio_director 側の render_local.py・run_remote.py・launch.ps1 も読んでよい(~/radio_director と ~/arg-render は読み取りだけ)
4. Mac 側の arg-render で画像段まで回すことはできるか。今 Mac で書き出しているときの流れと、画像段を足すときに足りないもの
5. Forge への呼び出しを ComfyUI に置き換えるときの変更範囲。案を2〜3通り出す。例:
   - 案A: ARG の画像生成クライアントに ComfyUI 実装を足し、Mac の arg-render で画像段も回す(Windows を使わない)
   - 案B: Windows の ARG のまま、送り先だけ B70 の ComfyUI にする(Windows は起こすが GPU は使わない)
   - 案C: forge-remote の forge-gen を共通の生成部品として呼ぶ
   それぞれの変更量・壊れやすさ・既存の手順書(radio_director の docs/commands/script.md など)への影響・テストのしかた
6. 推奨の案と、その実装を何本のブリーフに分けるか(どのリポジトリで何をするか)

## 制約
- コード・設定・手順書は変えない。報告と STATUS.md への追記だけ
- Windows 機・B70 機・Forge・ComfyUI に接続しない(読むのはリポジトリ内と上に挙げたパスだけ)
