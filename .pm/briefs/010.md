# パンの滑らかさと動きの量、章タイトルの帯と日付の重なりを直す

## 背景
auto_radio_generator-009 で、画像の場面分割とパンを入れた。今の設定は 1.05 倍に拡大し、crop の x を 96*t/D で動かすもので、エンコーダーは libx264 ultrafast。
Wi-Fi の回(2026-10-24、https://www.youtube.com/watch?v=tJaEMaxLS1M)を PM が見た感想は次のとおり。
- パンが少しカクカクしている
- 動きが小さすぎて、効いているか分からない

同じ回のコマで、章タイトルの帯が横に長い章(「電波はどこで弱まる？ 距離・壁・水と金属」「まとめ: 仕組みを知れば置き場所は変えられる」)は、右上の日付(2026/10/24)と少し重なっていた。

## やること
1. **パン**
   - カクつきの原因を突き止めて直す(整数ピクセル単位で crop 位置が動いている、など。原因はコードと実測で確かめる)。
   - 動きの量は、見て「ゆっくり動いている」と分かる程度まで増やす。ゆっくりしたズームを組み合わせるかどうかも含め、量と方式は任せる。
   - 速さは場面の長さ(約 90 秒)で決まるので、短い場面でも速すぎないようにする。
   - レンダリング時間が大きく延びる方式は避ける。今は 14 分の動画が約 7 分でできている。延びる場合は数字を報告する。
2. **章タイトルの帯**: 右上の日付と重ならないようにする。折り返し位置・帯の最大幅・日付の位置のどれで直すかは任せる。
3. **確かめ方**: 直した後のパンを、短い試しの動画(1 場面ぶん程度)で確かめる。
   - 数枚のコマの見比べに加え、コマごとの移動量が一定であることを数字で示す。
   - 章タイトルは、長い題(上の 2 つ)で日付と重ならないコマを示す。

## 制約
- 既存のテストは変えない(仕様が変わってどうしても必要なら、理由を報告に書く)。
- テストは arg-remote test で Windows 上で通す。
- merge は本番に配備されるので、PM が報告を見てから行う。
- config で切り替えられる値は config.yaml に置き、既定値は新しい方式にする。

## 報告に書くこと
- カクつきの原因と直し方
- 動きの量(前後の比較)
- 試しの動画のコマの場所
- レンダリング時間への影響
- 帯の直し方
