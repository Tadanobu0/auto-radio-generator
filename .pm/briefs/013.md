# visuals の avoid の型を仕様に合わせ、visuals の警告と画像プロンプトを Mac から見えるようにする

## 背景
011 で SceneVisual.avoid を「str か null」だけを受ける strict な型にした。しかし interface_spec §12(life-update-radio-specs、v1.11.0)では、avoid は List[str] になっている。011 のブリーフの要約が誤っていた。

radio_director-019 で、Wi-Fi の回の写しに List[str] の avoid を付けて流した。visuals の内容は次のとおり。
- deep_dive_1: 3 場面
- deep_dive_2: 4 場面
- deep_dive_3: 4 場面

ところが絵はどの章も 2 枚で、今の 90 秒の枚数のままだった。不正として scene_splitter に戻ったと見ている。
その警告は Windows のログにしか出ず、Mac の result.json の warnings は空だった。

## やること
1. 今回の run(E:\windsurf\auto_radio_generator\output\20261025_095449)のログ・prompt_report.md で、3 章が不正として捨てられたか、理由は何かを確かめる。
   - 理由が型以外(場面数の上限、90 秒の枚数の制限、max_scenes_per_chapter など)なら、それも直す。
2. avoid は List[str] を正とする。str が来たときも、要素 1 つのリストとして受ける。
   - ほかにも interface_spec §12 と食い違う点があれば、仕様に合わせる。
   - 仕様を読めない場合は、ここに書いた要約に従う: start_turn・focus・draw は必須、avoid は任意の List[str]。
3. visuals を不正として捨てたときの警告を、result.json の warnings に入れる(Mac に返るのはここだけ)。
   - result.json は radio_director 側の run_remote.py が書いている。こちらは WorkflowResult などに警告を載せるところまでにして、run_remote.py 側に要る変更を報告に書く。
4. 画像プロンプトの記録(prompt_report.md・generation_metadata.jsonl など)は、Mac が取り寄せられる場所・形で残す。
   - パスの決め方と形式を報告に書く。Mac 側の取り寄せは、radio_director の次のジョブで行う。
5. 019 の写しと同じ形(avoid がリスト、3〜4 場面)の試験用 JSON で、3 章とも visuals どおりの場面数・draw になることをテストで確かめる。

## 制約
- テストは arg-remote test で通す。
  - 既存のテストを変える場合は、理由を報告に書く。
  - 011 で足した、avoid の型を確かめるテストは、仕様に合わせて変わる見込み。
- merge は本番に配備されるので、PM が報告を見てから行う。
