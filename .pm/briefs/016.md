# 画像だけを先に作る実行・場面の作り直し・作った画像の使い回し、と置き場所の検査の誤判定の修正

## 背景
加湿器の回(radio_director-022、Windows の output\20261026_234722)で、置き場所が助言と逆の絵が 4 場面出た(テレビの真下・子どもの手が届く低い台・窓際・枕元)。原因は次の 2 つ。
1. 台本の構図の規則で、draw に「目の高さから見た絵」と書くようになった。014 の置き場所の検査が、その「eye-level / eye height」を物の高さの語とみなして不合格にした。17 場面中 5 場面が、短い代わりのプロンプト(_short_scene_prompt)に落ちた。
2. 短い代わりのプロンプトには avoid が入らず、置き場所の言い回しも弱い。外れた 4 場面は、すべてこの場面だった。

また今は、絵を見るのが全部できた後(約 13 分後)なので、1 枚外れても全体を作り直すことになる。画像だけを先に作って検品し、外れた場面だけを作り直してから本番を流す形にしたい。
Mac 側(radio_director の render_local.py → radio-render → launch.ps1 → run_remote.py)は、別のジョブで並行して直す。下の「受け渡しの形」は両方のジョブで同じものを使う。

## やること
### A. 誤判定と代わりのプロンプト
1. 置き場所の検査(scene_placement_check)で、視点を表す言い方を物の高さとみなさない。
   - 例: eye-level view / at eye level / seen from eye level / 目の高さから見た
   - 台本側でも言い方を「正面から見た部屋の絵」に替える(別ジョブ)が、古い台本のために両方で直す。
2. 短い代わりのプロンプトにも、avoid を「逆の状態を肯定形で」入れる。
   - 例: 窓際を避ける → away from the window, toward the middle of the room
   - 置き場所・高さ・距離の語を落とさない。

### B. 画像だけを先に作る実行(受け渡しの形)
run_workflow_sync に次を足す。指定が無ければ、今までどおりの動き。
1. `images_only=True`: 台本の読み込み・場面の区切り・背景画像の生成までで止める。音声・字幕・エンコード・アップロードはしない。
   - 結果(WorkflowResult)に、場面ごとの一覧を載せる。欄は segment_id・scene_index・画像の絶対パス・scene_visual・プロンプト・seed・cached。
   - result.json 用の欄を返す関数も用意する(012 の build_upload_result_fields と同じ形)。欄名は `scene_images`。
   - 画像は run の出力ディレクトリの下にコピーして置き、Mac が scp で取れるようにする。
2. `regen_scenes=[segment_id, ...]` と `regen_seed_offset=N`: 指定した場面だけ、キャッシュを使わず、seed をずらして作り直す。
3. `reuse_images_from=<前の images_only の run の出力ディレクトリ>`: 本番の実行で、その run の場面の画像をそのまま使う。
   - segment_id で対応づける。対応しない場面は、今までどおり作る。
   - 使い回したことと、対応しなかった場面を warnings に残す。
4. 2 と 3 は一緒に使える。例: 前の run の画像を使い回し、指定の場面だけ作り直す。

### C. テスト
- A: 加湿器の回の 5 場面の draw(eye height を含むもの)で、検査が誤って落とさないこと。短いプロンプトに avoid が入ること。
- B: images_only で音声以降に進まないこと、regen_scenes で指定の場面だけ seed が変わること、reuse_images_from で画像が同じファイルになること。
- 既存のテストは変えない。arg-remote test で通す。merge は PM が報告を見てから。
