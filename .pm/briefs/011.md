# 段 1: verified_script.json の visuals 欄を読んで、場面の区切りと画像プロンプトに使う

## 背景
Wi-Fi の回(2026-10-24)は、場面分割とパン(009/010)で絵が場面ごとに替わるようになった。ただし次の 3 つが残った。
- P1: deep_dive_3 の後半で、ルーターが窓際の床に直置きになっていた。台本の「床への直置きは避けて」と逆の絵
- P2: deep_dive_1 は 2 場面とも「電子レンジと黒いルーター」で、ほぼ同じ構図
- P3: メッシュ(複数台)の話なのに、機器が 1 台しか描かれない

原因は、画像側が台本の抜粋から絵を考えていること。そこで、台本側が場面ごとに「何を描くか・描いてはいけないか」を visuals 欄で渡すことに決めた。
仕様は life-update-radio-specs の interface_spec.md §12(v1.11.0)と visuals_proposal.md(§7 段 1)。読めるなら /Users/tada/life-update-radio-specs/ を読む。読めない場合は下の要約に従い、その旨を報告に書く。

### 仕様の要約(§12)
- 各章(segment)に任意の `visuals`(SceneVisual のリスト)が付く。
- SceneVisual は次の 4 つ。
  - `start_turn`(int、章の中のターン番号。0 始まり)
  - `focus`(str、場面の要点)
  - `draw`(str、描くもの: 主役・台数・置き場所など)
  - `avoid`(str、任意。描いてはいけないもの: 台本の助言と逆の状態など)
- 不正の条件は次のとおり。
  - start_turn が範囲外、昇順でない、先頭が 0 でない
  - 場面数が 0、または 5 以上
  - draw が空
  - 必須欄が無い、または型が違う
  - visuals が空リスト
- 不正なときは**その章だけ**今の scene_splitter に戻し、警告をログに残す。レンダリングは止めない。
- visuals が無い章(None)は今までどおり。
- avoid はネガティブプロンプトに入れない。画像プロンプトを作る段階で、その状態にならない描き方(例: 床置き → 棚や台の上)に反映させる。
- 章・ターンの実際のキー名は、このリポジトリの loader に合わせる。

## やること
1. 着手前に確かめる:
   - loader が未知のキーを拒むか(pydantic の extra 設定)
   - 今の scene_splitter の入出力
   - プロンプト生成の LLM 呼び出しの単位
2. visuals がある章は start_turn で場面を切る。focus・draw・avoid から画像プロンプトを作る。場面の時刻は、今の字幕・音声の時刻への対応づけを流用する。
3. 無い章・不正な章は今のまま scene_splitter を使う。

## 受け入れ条件(visuals_proposal §7)
- **1-a**: visuals の無い既存の verified_script.json(直近 2〜3 本)で、場面の区切りと画像プロンプト生成への入力が変更前と同じ。
- **1-b**: 範囲外・逆順・場面 0・5 場面などの試験用 JSON で、その章だけ scene_splitter に戻り、警告が出る。ほかの章は visuals どおりになる。
- **1-c**: Wi-Fi の回で効果を確かめる。
  - Wi-Fi の回の verified_script.json(Mac の /Users/tada/radio_director/output/script/2026-10-24_11-31_wi-fi/verified_script.json)の写しに、visuals を手で書き足す。
  - visuals の案はこのジョブが作り、報告に全文を載せる。
  - アップロードなしでレンダリングし、コンタクトシートで次を確かめる。
    - P1: 配置の場面で床置きになっていない。英語のプロンプトに on the floor などが無い
    - P2: deep_dive_1 の 2 枚の主役が違う。周波数帯の場面のプロンプトに microwave が無い
    - P3: メッシュの場面で、機器が 2 台以上、プロンプトに台数の語がある
  - プロンプトが正しいのに絵が従わない場合は、画像モデルの限界として記録する。不合格にはしない。
  - ファイルが読めない、またはアップロードなしでレンダリングする手段が無い場合は、そこで止めて要判断事項に挙げる。
