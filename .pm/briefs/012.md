# Windows 側の実行に「アップロードしない」スイッチを足す

## 背景
visuals(011)の効果を Wi-Fi の回で確かめたいが、Mac から /render を流すと必ず YouTube に限定公開で上がる。
試すたびに動画が増えるうえ、チャンネルは警告を受けている最中で、題が同じだと重複判定にも当たる。
そこで、動画は本番と同じに作り、公開だけを飛ばす実行を用意する。
Mac 側(radio_director の render_local.py → radio-render → launch.ps1 → run_remote.py)の改修は、次のジョブ(radio_director-018)でこの報告をもとに行う。

## やること
1. run_remote.py → run_workflow_sync の流れに「アップロードしない」スイッチを足す。
   - 音声・画像・字幕・エンコードは本番と同じに通す。YouTube への公開(サムネの設定を含む)だけを飛ばす。
   - 既存の設定(user_settings.json など)で切れるならそれを使い、無ければ足す。
   - 既定は今までどおりアップロードする。
2. result.json に、アップロードしなかったことと mp4 のパスが分かるように書く。今の result.json を読む側が壊れない形にする。
3. Mac 側から指定する方法(run_remote.py の引数、環境変数、launch.ps1 への渡し方など)を決め、報告にはっきり書く。radio_director-018 のブリーフにそのまま写せる粒度で書く。
   - launch.ps1 がこのリポジトリに無く、radio_director 側にあるなら、その旨と、launch.ps1 側で要る変更も書く。

## 制約
- テストは arg-remote test で通す。既存のテストは変えない。
- merge は本番に配備されるので、PM が報告を見てから行う。
