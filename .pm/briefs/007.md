# 画像プロンプトの指示文の改善(調査 006 の「小」)

## 背景
調査 006(.pm/reports/006.md)で、絵と話のずれの主因は画像プロンプトの指示文にあると分かった: 指示文の例 1 が「枕元のテーブルにセンサーとインスリンペン」で健康系の話題が引っ張られる / 「画面・表示のある機器は描かない」の決まりで CO2 モニターが正体不明の箱になる / 医療寄りの構図の指示で健康の話題が医療機器の見た目に寄る / LLM に渡す本文が章の先頭 800 字だけ / 否定語の前置き(screen・faces)が逆に物を呼び込む。

## やること(`services/script_generation/image_prompt_generator.py` が中心)
1. `SYSTEM_PROMPT_TEMPLATE` の例 1 を、寝室・医療機器でないものに替える。`_get_composition_guidance` の医療の項を「その話題の物そのものを細部まで」に改め、健康系の話題が医療機器の見た目に寄らないようにする
2. 小さな機器の表示部は「暗い表示窓、または色の付いた光だけ」を許す(数字・文字は描かせない)
3. プロンプトに、主役の物・大きさ・材質・置き場所・画面に占める大きさ(4〜6 割)を必ず書かせる
4. LLM に渡す本文を、先頭 800 字から章全体の要所(各 key_claim の最初のターン前後。無ければ章を等分した位置のターン)に変える。合計の長さの上限は今までと同程度でよい
5. 否定語の前置きを短くし、「screen」「faces」のように物を呼び込む語を減らす(「人物のいない」「文字のない」のような肯定形の言い回しを優先)
6. CO2 の回(Windows 側 `E:\windsurf\auto_radio_generator\output\20261022_125319` の prompt_report.md など)の実際のプロンプトを読めれば読み、例 1 に引っ張られていたかを確認して報告する。arg-remote では読めないので、読めなければ「未確認」と書く

## 確認の方法
- `~/cc-bridge/bin/arg-remote sync` → `~/cc-bridge/bin/arg-remote test -q`(Bash の timeout 3600000)。
- レンダリング・画像生成はしない(効果は次の /render のコマで見る)。

## 制約
- 既存テストは変えない。追加テストで確認(LLM はモック)。
- pip install・本番ツリーの操作はしない。
- 要判断事項は本当に要るものだけ。無ければ「- なし」。
