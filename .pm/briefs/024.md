# サムネイル背景の自動プロンプトが抽象画になる問題を直す

## 背景
- 候補 9 枚方式(ブリーフ 021)を本番で 2 回使った(radio_director 080「寝る前のスマホ」・081「ヒートショック」)。場面画像はほぼ 1 回目から選べたが、**サムネイル背景は 2 回とも 9 枚全部が「光の網・結晶・粒子」のような抽象画**で、題と合わず 0/9 だった。Mac 側がプロンプトを上書きして作り直すと 1 回で合格した。
- 上書きして合格したプロンプトの要点(2 回とも同じ型):
  - 080: 夜の寝室を正面から。右 3 分の 1 に小さなベッド脇の台、伏せたスマホ 1 台、暖色の卓上ランプ。左 3 分の 2 は無地の暗い藍色の壁で、題の余白にする。人・文字・ロゴなし。
  - 081: 冬の夜の家庭の浴室を正面から。湯気の立つ白い浴槽と木の風呂桶を右 3 分の 1 に、左 3 分の 2 は題の文字のための無地の壁。人・文字・窓なし。
- 上書き前の自動プロンプト(抽象画になったもの)は、Mac 側の回収物 `arg_scene_images.json` の `thumbnail_bg.prompt` と、ARG の出力ディレクトリの generation_metadata にある(radio_director の `output/renders/20261110_032222`・`20261111_122851`。Mac の ~/arg-render の output 側にも同じ回の記録があるはず)。

## やること
1. サムネイル背景のプロンプトを作っている所(`thumbnail_background_generator.build_prompt` と、LLM に頼む `generate_thumbnail_prompt` の指示文)を読み、080・081 の 1 回目のプロンプトと、上書き後のプロンプトを並べて、なぜ抽象画に寄るかを突き止める(指示文に「abstract」「background texture」のような語があるか、題や場面の具体物を渡していないか、など)。
2. 自動のプロンプトに、次を固定で入れる(LLM が作る部分はテーマの具体物に絞る):
   - 構図: 正面からの実在の場所・物の写実的な絵。テーマを表す**具体物**(場面画像と同じ方針で、人・顔・手・文字・ロゴ・ブランドなし)を**右 3 分の 1** に置く。
   - 余白: **左 3 分の 2 は無地の壁や空のような平らな面**にして、題の文字を乗せる余白にする(題は後から ARG が乗せる。サムネイルの題の位置・幅の仕様に合わせる。左寄せでないなら、その位置に合わせる)。
   - 避ける: 抽象画・光の網・結晶・粒子・ボケた光の模様・グラデーションだけの絵。
3. 080・081 の台本(verified_script は Mac の radio_director の output/script/2026-11-09_23-16_theme と 2026-11-11_08-48_theme。取れなければ tests の fixtures の台本)で `build_prompt` の出力を前後で比べ、報告に貼る。画像は作らない(ComfyUI・GPU は使わない)。
4. テストは追加のみ。既定の場面画像のプロンプトは変えない。

## 守ること
- 変えるのはサムネイル背景のプロンプトだけ。場面画像・本番の流れ・出力の形は変えない。
- `.env`・認証情報は読まない。

## 報告
- 原因、変更した指示文の前後、080・081 でのプロンプトの前後、テストの件数。
- テストは PM 側(ユーザーが Mac の worktree から `arg-remote sync` → `arg-remote test -q`)で流す。ジョブで pytest を実行できたら結果を、できなければ未実行と理由を書く。
