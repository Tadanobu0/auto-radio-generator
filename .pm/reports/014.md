## 1. deep_dive_2_scene1 が汎用の文になった原因
- **ログは見ていません**: arg-remote のサブコマンドは status / sync / test / deploy / release-session だけで、本番の output を読めません。worktree の外も読めません
- **原因(コードからの見立て)**: その文は `_get_fallback_prompt` の deep_dive 用の固定の文です。ここに落ちる道は 2 つだけです
  1. LLM の出力が長すぎた(前置き込みで 1000 字超)
  2. LLM の呼び出しが例外になったか、空を返した
- 約 18.6 秒かかった(ほかは約 10 秒)ことから、1 とみています。出力が上限(512 トークン、約 2000 字)近くまで伸びると、LLM の時間が数倍になります。2 の接続エラーなら、すぐ落ちるか、再試行の待ち(1 + 2 秒)が入るだけです
- **ログに出なかった理由**: 失敗は Python の logging(warning / error)にしか出しておらず、processing_log.txt と warnings には載りませんでした
- PM が確かめる場合: generation_metadata.jsonl の deep_dive_2_scene1 の行
  - `generation_time_sec`(FLUX だけの時間)がほかの場面と同じ(約 10 秒)なら、増えた約 8 秒は LLM 側です
  - Windows の Python のログ(コンソール)に `Generated prompt too long for deep_dive_2_scene1: N chars > 1000` があれば 1 で確定。`Prompt generation failed` なら 2 です

## 3. scene_visual がある場面の流れ
1. 通常どおりプロンプトを作る。失敗(例外・空・1000 字超・置き場所のチェック)したら、何が悪かったかを `CORRECTION:` として添えて、1 回作り直す
2. 2 回ともだめなら、LLM に focus・draw(avoid は「逆の状態を描く」)を 1 文の英語に訳させ、前置き・配色・フィルムの語を付ける(max_tokens 160、temperature 0.2)
3. 2 も LLM が答えないときは、退けた出力を使う(置き場所が崩れたものはそのまま、長すぎたものはカンマで切る)。汎用の文は、LLM がまったく答えないときだけ
- 1 場面の LLM 呼び出しは最大 3 回です。うまくいく場面は 1 回のままです
- visuals の無い場面は従来どおりです(作り直さず汎用の文)。warnings だけ足しました

## 4. 置き場所・高さの指示とチェック
- 指示: step 1 に足しました。「draw の置き場所・高さ・位置の語を、家具や場所の言葉として英語に残す(腰の高さの棚 → on a waist-height shelf、部屋の中央寄り → toward the middle of the room)。高さの語は大きさではないので、機器の大きさは別の語(palm-sized 等)で書く」
  - step の数は変えていません。既存テストが番号の並びを見ているためです
- チェック(`scene_placement_check.find_placement_problem`)は、次の 2 つを弾きます
  - draw に高さの語(腰の高さ・胸の高さ・目の高さ 等)や床から離す語(高い位置・床から離・壁掛け 等)がある、または avoid が床置き・低い位置を避けるのに、プロンプトに `on the floor` / `at floor level` / `low shelf` / `low wooden table` 等がある
  - draw の高さの語が、プロンプトで家具に付かず機器に付いている(`waist-high white router`)。`at waist height` と `waist-height wooden shelf` は通します
- 語が無いこと(高さを書き落としただけ)は弾きません。draw 自身が床に物を置く場面(「床に置いた加湿器」)は床のチェックをしません
- 019 の deep_dive_3_scene3 の文("one waist-high white router on a low shelf …")は、2 つとも当たります
