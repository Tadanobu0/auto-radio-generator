## 確かめたこと

## Mac 側からの指定方法(決定)
**環境変数 `ARG_NO_UPLOAD=1` を、run_remote.py を起動するプロセスにだけ設定します。** run_remote.py では、引数 `--no-upload` を受けて `skip_upload=True` を渡すことも推奨します(下の 2)。

```
Mac: render_local.py --no-upload
  → radio-render --no-upload
    → ssh gtune-lan powershell ... launch.ps1 -NoUpload
      → $env:ARG_NO_UPLOAD = "1"; python run_remote.py ... --no-upload
        → run_workflow_sync(..., skip_upload=True)   # 環境変数だけでも止まる
```

環境変数だけで止まるので、run_remote.py の改修が遅れても公開は止められます。ただし result.json に「アップロードしなかった」と書くには run_remote.py の改修が要ります。

## radio_director-018 に写す内容

### 前提: 順序
1. 先にこの 012 を merge・deploy する(`arg-remote deploy`)。**deploy 前の本番は `ARG_NO_UPLOAD` を見ないので、スイッチを付けても公開されます。** また run_remote.py が `skip_upload=` を渡すと TypeError になります
2. その後で 018 を配備する。run_remote.py は結果に `upload_skipped` 属性があるか(`hasattr(result, "upload_skipped")`)を見て、無ければ「本番が古い」とエラーにすると安全です

### 1. launch.ps1(radio_director 側)
- 引数に `[switch]$NoUpload` を足す
- `$NoUpload` のときは run_remote.py を起動する前に `$env:ARG_NO_UPLOAD = "1"` を設定し、run_remote.py に `--no-upload` を付ける
- `$NoUpload` でないときは `Remove-Item Env:ARG_NO_UPLOAD -ErrorAction SilentlyContinue` で消しておく(親から引き継いだ値で本番の公開が止まらないように)
- **注意**: launch.ps1 が run_remote.py を直接起動せず、スケジュールタスク(`RadioRemote`)経由で起動している場合、`$env:` はタスクのプロセスに届きません。その場合は、タスクが読む依頼ファイル(または引数)に `no_upload: true` を書き、run_remote.py がそれを読んで `skip_upload=True` を渡す形にしてください
- 環境変数をマシン全体やユーザー全体(`setx`・`[Environment]::SetEnvironmentVariable(..., "User")`)に設定しないでください。本番の公開も止まります

### 2. run_remote.py(radio_director 側)
- 引数 `--no-upload`(`action="store_true"`)を足し、`run_workflow_sync(..., skip_upload=args.no_upload)` を渡す。既定は False(今までどおりアップロード)
- result.json を書くところで、今の欄はそのままにして、次の欄を足す:
  ```python
  from workflow import build_upload_result_fields
  for key, value in build_upload_result_fields(result).items():
      data.setdefault(key, value)   # 既にある欄は上書きしない
  ```
  足される欄:
  | 欄 | 型 | 値 |
  |---|---|---|
  | `upload_skipped` | bool | アップロードしない実行で公開を飛ばしたら true |
  | `upload_status` | str | `"uploaded"`(公開した)/ `"skipped"`(アップロードしない実行)/ `"not_uploaded"`(設定で無効・Mock・アップロード失敗) |
  | `video_path` | str または null | mp4 の Windows 上の絶対パス(例 `E:\windsurf\auto_radio_generator\output\20261025_120000\...mp4`) |
- 今の result.json に既に `video_path` などの同名の欄があれば `setdefault` で元の値が残ります。意味が違う場合は 018 で欄名を合わせてください(今の欄名は私は見ていません)
- アップロードしない実行では、今の URL の欄(`uploaded_video_url` などに相当するもの)は null / 空になります。success は true のままです

### 3. radio-render / render_local.py(Mac 側)
- `--no-upload` を受けて launch.ps1 に `-NoUpload` を渡す
- result.json を読む側は、`upload_status == "skipped"` のときに URL が無いことを失敗扱いにしない。mp4 は `video_path` から取り寄せる(scp など。Windows の絶対パスなので、取り寄せ方は 018 で決める)
- `upload_skipped` の欄が無い result.json は「古い本番か、スイッチが届いていない」とみなす
