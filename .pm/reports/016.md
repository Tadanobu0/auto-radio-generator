# 報告 016: 画像だけを先に作る実行・場面の作り直し・作った画像の使い回し、と置き場所の検査の誤判定の修正

## 状態
完了。置き場所の検査は「目の高さから見た」「eye-level view」などの視点の言い方を高さとみなさなくなりました。短い代わりのプロンプトには、avoid の逆の状態(肯定形)と draw の高さ・距離の語をコードで足します。`run_workflow_sync` に images_only / regen_scenes / regen_seed_offset / reuse_images_from を足しました。指定が無ければ今までどおり動きます。arg-remote で全テストが通っています。

## 受け渡しの形(確定。Mac 側のジョブと突き合わせる用)

### 引数(`workflow.run_workflow_sync`)
| 引数 | 型・既定 | 動き |
|---|---|---|
| `images_only` | `bool = False` | True なら、台本の読み込み → 場面の区切り → 背景画像の生成で止める。音声・字幕・エンコード・メタデータ・サムネ・アップロードはしない |
| `regen_scenes` | `list[str] \| None = None` | 作り直す場面の segment_id(例 `["deep_dive_2_scene3"]`)。キャッシュを使わず、seed をずらして作り直す |
| `regen_seed_offset` | `int \| None = None`(None なら 1) | seed のずらし幅。seed = 前の run の seed + N。前の seed が分からなければ、segment_id のハッシュから決めた値 + N |
| `reuse_images_from` | `str \| None = None` | 前の images_only の run の出力ディレクトリ(Windows のパス)。その中の `scene_images.json` を読み、segment_id が合う場面はその画像をそのまま使う |

- regen_scenes と reuse_images_from は一緒に使えます(前の画像を使い回し、指定の場面だけ作り直す)。images_only と組み合わせても、本番の実行で使ってもかまいません
- reuse_images_from のディレクトリに `scene_images.json` が無い・読めないときは、台本を読む前に `success=False` で止まります(`error_message` は `reuse_images_from: ...\scene_images.json not found ...`)
- `images_only` の WorkflowResult: `success=True`、`images_only=True`、`video_path` / `audio_path` / `subtitle_path` は None、`upload_skipped=True`(このため `build_upload_result_fields` の `upload_status` は `"skipped"`)。`output_dir`・`warnings`・`prompt_report_path`・`generation_metadata_path` は今までどおり入ります

### result.json の欄
`workflow.build_scene_images_result_fields(result)` が `{"scene_images": [...]}` を返します(012 の `build_upload_result_fields` と同じ使い方です)。各要素の欄は次のとおりです。
| 欄 | 中身 |
|---|---|
| `segment_id` | `deep_dive_2_scene3` の形。場面が 1 つの章は章の id のまま(`intro` など) |
| `scene_index` | 章の中の 0 始まりの番号(`_sceneN` の N − 1。場面が 1 つの章は 0) |
| `image_path` | 画像の絶対パス(Windows 上)。images_only の run ではコピー先(下記) |
| `scene_visual` | 台本の SceneVisual(`start_turn` / `focus` / `draw` / `avoid`)。visuals の無い章は null |
| `prompt` | 画像のプロンプト。静止画に落ちたときは null の場合があります |
| `seed` | 使った seed。キャッシュの画像・静止画など、seed が分からないときは null |
| `cached` | キャッシュの画像を使ったら true |
| `source` | `"generated"`(今回作った)/ `"cache"`(キャッシュ)/ `"reused"`(reuse_images_from の画像)/ `"static"`(静止画に落ちた)。ブリーフに無い欄ですが、確認用に足しました |

- 一覧は場面の順(動画に出る順)です
- 本番の実行(images_only でない)でも `WorkflowResult.scene_images` は埋まります。ただし画像はコピーせず、実際に使ったパスを指します(キャッシュか、前の run の scene_images の下)

### 画像の置き場所
- images_only の run: `<run の出力ディレクトリ>\scene_images\NN_<segment_id>.png`(NN は 01 から始まる場面の順の番号)。一覧は `<run の出力ディレクトリ>\scene_images.json` に `{"scene_images": [...]}` として書きます(result.json の欄と同じ中身)
- run の出力ディレクトリは今までどおり `output\<YYYYMMDD_HHMMSS>`(`result.output_dir`)。Mac はここから scp で取ります
- run のディレクトリを移しても、`scene_images.json` の中の絶対パスが無ければ、同じファイル名を `<移した先>\scene_images\` から探します
- 作り直した画像のキャッシュは `output\.image_cache\<プロンプトのハッシュ>_seed<N>.png` に書きます。元のキャッシュの画像は上書きしません

### warnings(reuse_images_from を使ったとき、result.json の warnings に入る)
- `reused 15 scene image(s) from <dir>: intro, deep_dive_1_scene1, ...`
- `no reusable image in <dir> for 1 scene(s), generated as usual: deep_dive_3_scene1`(今回の場面のうち、前の run に無かったもの)
- `1 scene image(s) of <dir> matched no scene of this run: deep_dive_2`(前の run の画像のうち、使わなかったもの)
- `scene image for <id> in <dir> is missing; generated as usual`(一覧にはあるが、ファイルが無いもの)

### run_remote.py 側の使い方の例(Mac 側ジョブ向け)
```python
from workflow import build_scene_images_result_fields
result = run_workflow_sync(..., images_only=True)                      # 1. 画像だけ
result = run_workflow_sync(..., images_only=True,                      # 2. 外れた場面だけ作り直す
                           reuse_images_from=str(prev_output_dir),
                           regen_scenes=["deep_dive_2_scene3"], regen_seed_offset=1)
result = run_workflow_sync(..., reuse_images_from=str(last_images_dir))  # 3. 本番
for key, value in build_scene_images_result_fields(result).items():
    result_json[key] = value
```

## 変更ファイル
- `services/script_generation/scene_placement_check.py` — 視点の言い方を取り除いてから高さを見るようにしました。draw 側は「目の高さから」「目の高さで見た」「目の高さの視点」などを外します(腰・胸・肩も同じ)。プロンプト側は `at/from eye level`、`seen/viewed/shot from eye height`、`eye-level (frontal) view/shot/camera/perspective…` を外します
- `services/script_generation/scene_placement_phrases.py` — 新規。短いプロンプトに足す語句を作ります。draw の高さ(`at waist height`)と距離(`壁から30cm離す` → `with about 30 centimeters of open space around it`)、avoid の逆の状態です。逆の状態は表で決めた肯定形で、窓際 → `away from the window, toward the middle of the room`、テレビ・家電 → `on its own stand with open space around it, apart from other appliances`、手が届く・低い台 → `up on a high shelf, well above the floor`(draw が高さを決めているときは `raised up off the floor`)、床・直置き → `raised up off the floor`、枕元・ベッド → `a few steps away from the bed, across the room`、壁際、カーテン・家具、エアコンの風、直射日光、部屋の隅、の各項目があります。LLM の文にもう同じ意味の語があれば足しません
- `services/script_generation/image_prompt_generator.py` — 短いプロンプトの LLM の 1 文の後ろに、上の語句を足すようにしました。LLM への指示にも「Must not be shown の各項目は、どこにあるかを肯定形で書く(窓際 → away from the window, toward the middle of the room)」と「距離の語も残す」を加えました
- `services/media_processing/scene_images.py` — 新規。`SceneImageOptions`(作り直す場面・seed のずらし幅・使い回しの一覧)、`scene_images.json` の読み書き、run の下への画像のコピー、音声なしで場面を区切るための発話時間の見積もり
- `services/media_processing/image_provider.py` — 場面ごとの記録(`scene_records`)を足しました。前の run の画像の使い回し、作り直す場面でキャッシュを使わず seed を渡す処理、使い回しのまとめの警告(`finish_scene_images`)もここです

## テスト結果
- `arg-remote sync` のあと `arg-remote test -q tests/test_scene_images_016.py`(HEAD 99ab421): **28 passed**
- `arg-remote test -q`(HEAD 99ab421): **867 passed / 8 skipped / 0 failed**。015 の 839 件に新しい 28 件を足した数です。skip の 8 件は試しエンコードで、015 と同じです。既存のテストは変えていません
- テストの中身は次のとおりです
  - A: 加湿器の回の形の 5 場面(draw に「目の高さから見た」、プロンプトに eye-level view / seen from eye level / viewed from eye height / eye-level frontal view / eye-height camera・shot at eye level)で、検査が落とさないこと
  - A: 視点の言い方の隣にある本物の崩れ(`low shelf`、`waist-high humidifier`)と、置き場所の高さの「目の高さの棚」は、今までどおり落とすこと
  - A: 5 場面とも、短いプロンプトに avoid の逆と高さ・距離が入り、それでも検査を通ること
  - B: images_only では制作・メタデータ・サムネ・YouTube を呼ばないこと。画像のコピーと `scene_images.json` ができ、欄がそろうこと
  - B: regen_scenes の場面だけ、キャッシュがあっても seed を渡して作り直すこと(前の seed + N。不明ならハッシュ + N)。他の場面は seed を渡さないこと
  - B: reuse_images_from の場面は、前の run の同じファイルのパスを返し、作らないこと。合わない場面だけ作り、warnings を出すこと
  - B: 使い回しと作り直しを一緒に使えること、本番の実行にもこの指定が渡ること、指定が無ければ何も渡らないこと

## 未解決点
- visuals の無い章は、音声を作らないので、文字数から発話の長さを見積もって場面を区切ります(8 字/秒 × 話速、間は pause_between_phrases_ms)。本番の音声とずれて場面の数が変わると、その章の場面は使い回せません。その場合は今までどおり作り、warnings に出ます。visuals のある章は台本の start_turn で切るので、本番と一致します
- images_only でも、前提条件の確認(VOICEVOX・FFmpeg・素材)はそのまま通します。VOICEVOX が止まっていると images_only でも止まります。既存のテストのスタブの形を変えないため、ここは触っていません
- avoid の逆の状態の表に無い言い方は、LLM への指示(肯定形で書く)だけに頼ります。表に無い言い方で外れた場面が出たら、表に足します
- 加湿器の回(radio_director-022)の実際の draw・プロンプトは、このジョブから読めませんでした(Windows の output)。テストの 5 場面は、ブリーフの記述(目の高さから見た・テレビの真下・子どもの手が届く低い台・窓際・枕元)から作った写しです。実際の効き目は merge・deploy 後に、加湿器の回を images_only で流して確かめてください
- 受け渡しは、Windows の run_workflow_sync と Mac の run_remote.py の間の取り決めです。リサーチ側との interface_spec の欄は変えていないので、specs リポジトリは更新していません
