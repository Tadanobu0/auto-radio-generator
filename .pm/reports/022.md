## 1. 画像段の呼び出し方

### Forge のとき(`services/media_processing/flux_client.py`)
- API は **txt2img だけ**(`/sdapi/v1/txt2img`、`flux_client.py:196-199`)。img2img・hires fix・ADetailer などは使っていない
- 送る条件(`flux_client.py:143-154`): prompt / negative_prompt / steps / width / height / sampler_name / scheduler / cfg_scale / seed / batch_size=1。値は config.yaml の `flux:`(`config.yaml:588-610`。今は steps 8・768×432・Euler・Simple・cfg 1)
- ネガティブ: 固定の `"text, gibberish, fake text, distorted letters, writing, watermark, signature, logo, words, characters, alphabet"`(`flux_client.py:145`)。cfg 1 の FLUX schnell では効いていない(報告 006 の 5 と同じ)
- seed: 指定があればその値、無ければ `-1`(乱数)。使われた seed は応答の `info` の JSON から取る(`flux_client.py:152, 268, 308-342`)
- Forge だけの動き: 毎枚の**生成前に `/sdapi/v1/unload-checkpoint`** を呼ぶ(`flux_client.py:90-112, 157`。毎回モデルを下ろす)/ タイムアウトしたら解像度を下げて再試行(896×504 → 768×432 → 640×360、`flux_client.py:174-217`)/ 生成後に `torch.cuda.empty_cache()`(torch がある環境だけ、`flux_client.py:291-306`)

### ComfyUI のとき(`services/media_processing/comfyui_client.py`)
- `config/workflow_api.json` を読み、ノード番号を決め打ちで書き換える(`comfyui_client.py:29-37, 153-171`): 6 = 正のプロンプト、5 = 幅・高さ、3 = seed・steps・cfg・sampler・scheduler。ノード 7(ネガティブ "text, watermark")は書き換えない
- `POST /prompt` → 2 秒ごとに `GET /history/{id}` → `GET /view?filename=...&subfolder=&type=output` で取ってくる(`comfyui_client.py:190-261`)
- seed: 指定が無ければクライアント側で `random.randint(1, 10**15)`、記録もその値(`comfyui_client.py:160-162, 284`)
- 解像度の再試行・VRAM の後始末は無い。ワークフローの `filename_prefix` は "SD1.5"(`config/workflow_api.json:96`)で、ComfyUI 側の output に毎枚残る

### サムネイル背景
- 場面画像と**同じクライアント・同じ条件**(大きさ・steps・sampler も同じ)。違うのはプロンプト(`generate_thumbnail_prompt`)と `context_type="thumbnail"` だけ(`thumbnail_background_generator.py:36-56, 118-124`)
- 1280×720 への拡大は ARG の Pillow 側(`thumbnail_generator.py:21-22, 106-130`)

## 2. 画像段の機能が生成 API のどこに依存しているか
すべて `ImageProvider` / `scene_images.py` / `workflow.py` 側の処理で、生成 API に求めているのは **`generate_image(prompt, output_path, context_type, segment_id, segment_type, visual_identity, seed=None) → (path, metadata)` と、`metadata.seed` が実際の seed であること**だけ。Forge 固有の API は使っていない。

| 機能 | 実装の場所 | 生成 API への依存 |
|---|---|---|
| クライアントの選択 | `image_provider.py:99-119` / `thumbnail_background_generator.py:36-53` | `image_provider` が forge / comfyui |
| 1 枚ずつ順番 | `image_provider.py:45-47`(semaphore 1) | なし |
| キャッシュ(cached) | `image_provider.py:299-334`。キーはプロンプト全文の SHA-256、seed 指定時は `_seed<seed>`。置き場は作業ディレクトリからの相対 `output/.image_cache`(`:65`) | なし。**ただしキーに送り先・大きさが入っていない**ので、同じプロンプト・seed なら別の送り先の絵が出る |
| 候補(candidates)・一覧画像 | `image_provider.py:429-510`、`scene_images.py:142-150, 542-578`、`contact_sheet.py` | seed を指定して 1 枚ずつ呼ぶだけ。一覧画像の数字の字は `C:/Windows/Fonts/arial*.ttf`(`contact_sheet.py:27-28`)、Mac では Pillow の既定の字に落ちる |
| 作り直し(regen_scenes・regen_seed_offset) | `scene_images.py:171-183` | 前の seed + ずらし幅を渡すだけ。**同じ seed でも Forge と ComfyUI、4070 と B70 で絵は変わる**(前の回の続きにはならない) |
| prompt_overrides | `image_provider.py:385-427` | なし(プロンプトを差し替えるだけ) |
| reuse_images_from・picks | `image_provider.py:196-241`、`scene_images.py:423-484` | なし(生成しない)。パスの読み替えは `Path(...).name` なので、**Windows の `E:\...` のパスを Mac で読むとファイル名が取れない**(POSIX では `\` が区切りにならない) |
| サムネイル背景(018・021) | `workflow.py:1602-1792` | 場面と同じ |
| ロゴの検品 | ARG には無い(`logo` は前置き・ネガティブの文言だけ)。radio_director 側にあるなら、このジョブからは見られない | — |

## 4. Mac の arg-render で画像段まで回せるか
- **回せる見込みが高い**。Mac はすでに `run_workflow_sync`(本番。`reuse_images_from` + `reuse_strict` + `picks`)を回しているので、同じ関数に `images_only=True` を渡せば、場面の区切り → プロンプト → 生成 → `scene_images/` と `scene_images.json` → サムネイル背景まで ARG の中で済む(`workflow.py:676-743, 2256-2318`)
- 今の流れ(報告 016・019・021 から): Mac → Windows で images_only(候補・一覧画像)→ Mac で選ぶ → Windows で選び直し(必要なら)→ Mac で本番の書き出し(`reuse_images_from` に Windows の run を写したもの)。画像段を Mac に移すと、Windows との画像の行き来とパスの読み替えが無くなる
- 足りないもの(ARG 側):
  1. Mac の config で `image_provider: comfyui`・`comfyui.base_url: http://192.168.0.70:8188`・1344×768・steps 4・`sampler_name: euler`・`scheduler: simple` を指す方法(上のとおり config の場所が固定。Mac の checkout の config.yaml を書き換えるか、引数・環境変数を足す)
  2. B70 のワークフロー JSON をそのまま使えるか: ComfyUIClient はノード番号 3/4/5/6/7/9 を決め打ちしている。B70 の `flux1-schnell-fp8.api.json` の番号が違えば `Workflow structure mismatch` → **黙って静止画に落ちる**(warnings には出る)。ここは JSON を読めず未確認
  3. `/view` の `subfolder` を空で決め打ち(`comfyui_client.py:258`)。B70 側の `filename_prefix` にフォルダが入っていると取れない
  4. 2 秒刻みのポーリング(`comfyui_client.py:206-208`)。B70 で 1 枚が数秒なら、待ちの半分近くがポーリングの刻みになる(162 枚の候補で数分の差)
- radio_director / arg-render 側(読めていないので推測): 画像段を ssh で Windows に投げている所を、Mac のローカル実行に替える。Windows を起こす・使用中の判定・Forge の起動停止は画像段では要らなくなる

## 6. 推奨とブリーフの分け方
**推奨: 案A。** ARG にはもう ComfyUI のクライアントがあり、画像段の機能は全部その上で動くので、B70 に合わせる手直しで済む。Windows を起こす経路が画像段から消えるので、終了コード 20 も解消する。案C の「接続先を 1 か所にまとめる」利点は、B70 の URL とワークフローを設定に出せば A でもほぼ得られる。

ブリーフの分け方(3 本):
1. **ARG(auto_radio_generator)**: ComfyUIClient を B70 向けに直す。既定(Windows の今の動き)は変えない
   - ワークフローの差し替え位置を設定で持つ(ノード番号か class_type で探す)、`sampler_name` / `scheduler` を config から、`/view` の subfolder は history の値を使う、ポーリング間隔を設定に(既定 2 秒のまま)
   - config の切り替え口(例: `ARG_CONFIG=<yaml>` か、`run_workflow_sync(image_backend=...)`)。Mac の checkout の config.yaml を直接書き換える運用なら不要
   - 任意: キャッシュのキーに送り先・大きさを含める(混ざり防止)
   - テストは httpx のモックで追加のみ
2. **radio_director(+ arg-render)**: 画像段を Mac で `run_workflow_sync(images_only=True, ...)` として回す。Windows の画像段の経路は当面の予備として残すか消すか(下の判断)。docs/commands/script.md の更新
3. **確認ジョブ(小)**: Mac → B70 で同じ台本の images_only を 1 回流し、Windows の回と絵・時間(`image_generation_times`)を比べる。2 の最後に含めてもよい
