## 1. 019 の回で 3 章が捨てられた理由
- **ログは見ていません**: arg-remote には本番の output を読むサブコマンドがありません。worktree の外も読めません。テストの仕組みで本番のファイルを読むのは、権限の趣旨に反するのでやめました
- **原因(コードから確定)**: 011 の `SceneVisual` は strict で、avoid は「str か null」しか受けませんでした。List[str] の avoid が来ると、その場面は型エラーになります。019 の写しは各章の 1 場面目(scene 0)から avoid がリストなので、3 章とも不正になり、scene_splitter に戻ります。90 秒割りで 2 枚になり、症状と合います
  - 出ていたはずの警告: `visuals of deep_dive_1 is invalid (scene 0: missing or wrong type (avoid)); falling back to scene_splitter for this segment`(deep_dive_2・3 も同じ)
  - この警告は Python の logging にしか出しておらず、processing_log.txt には載りませんでした(今回から `[WARN]` で載ります)
- **型以外の制限は効いていません**:
  - 場面数の上限は 4 です。3・4 場面はどちらも通ります
  - `max_scenes_per_chapter` と 90 秒の枚数は、visuals がある章では見ません(scene_splitter に戻ったときだけ使います)
  - ターンの時刻はターン数と同じ数だけ作られます(1 ターン = 1 フレーズ)。そのため「時刻が無い」で捨てられることも、通常はありません
- PM が手で確かめる場合の置き場所(013 より前の配置):
  - 背景の記録: `output\20261025_095449\videos\prompt_report.md`
  - サムネの記録: `output\20261025_095449\prompt_report.md`
  - 場面が `deep_dive_1_scene1`・`deep_dive_1_scene2` の 2 つで、draw の文言が入っていなければ、上の見立てどおりです

## 2. avoid の型(仕様に合わせた)
- `SceneVisual.avoid: List[str]`(任意。既定は空リスト)
  - str 1 つは、要素 1 つのリストとして受けます
  - null と欄なしは、空リストとして受けます
  - 空白だけの要素は落とします
  - 要素が str でないもの(`1`、`["a", 1]`、`{...}`、入れ子のリスト)は不正です。その章は scene_splitter に戻ります
- プロンプトでは、要素を `; ` でつないで「- The picture must NOT show: …」の 1 行にします。要素が 1 つなら、011 と同じ文面です
- start_turn・focus・draw は必須のまま。仕様書(specs リポジトリ)は今回も読めなかったので、ブリーフの要約に従いました。ほかの欄は変えていません

## 3. 警告を result.json の warnings へ
- こちらでやったこと: 警告を **`WorkflowResult.warnings: list[str]`** に入れます。中身は次の 2 種類で、どちらも処理ログ(processing_log.txt)に `[WARN] …` で、完了時に「警告 N 件」として出ます
  - 読み込み時に不正として捨てた章: `visuals of <章> is invalid (<理由>); falling back to scene_splitter for this segment`
  - ターンの時刻が無くて捨てた章: `visuals of <章> ignored: …; falling back to scene_splitter`
- 運び方:
  - 読み込み時の分: `ScriptSegment.visuals_warning` → `ExternalScriptPhaseResult.warnings`
  - タイムラインの分: `TimelineCalculator.warnings` → `RenderResult.warnings` → `ProductionPhaseResult.warnings`
- **run_remote.py(radio_director 側)に要る変更**: result.json を書くところで、次を足してください。

  ```python
  import workflow

  warnings = data.setdefault("warnings", [])
  for message in getattr(result, "warnings", None) or []:   # 古い本番には無い
      if message not in warnings:
          warnings.append(message)
  build_prompt_fields = getattr(workflow, "build_prompt_log_result_fields", None)  # 013
  if build_prompt_fields is not None:
      for key, value in build_prompt_fields(result).items():
          data.setdefault(key, value)
  ```
  - 今の result.json の `warnings` が文字列のリストでなければ、そちらの形に合わせてください(中身は見ていません)
  - 失敗時(`success: false`)の WorkflowResult では、warnings は空です

## 4. 画像プロンプトの記録(Mac から取り寄せる形)
- **場所**: run のディレクトリ(`WorkflowResult.output_dir`。例 `E:\windsurf\auto_radio_generator\output\20261025_120000\`)の直下
  - `generation_metadata.jsonl`(機械向け。1 行 1 枚)
  - `prompt_report.md`(人向け)
  - 背景(場面ごと)とサムネの両方が、この 2 ファイルに書かれます。013 より前は、背景の分は `videos\` の下、サムネの分は直下と分かれていました
- **パスの渡し方**: `build_prompt_log_result_fields(result)` が result.json 用に `prompt_report_path` / `generation_metadata_path` を返します。値は Windows の絶対パスで、無ければ null(静的背景のときなど)
  - Mac 側は、この 2 つを `video_path` と同じ方法(scp など)で取り寄せてください
- **jsonl の 1 行の欄**:
  - 前からある欄: `timestamp` / `image_path` / `context_type`(`segment` か `thumbnail`)/ `segment_id`(例 `deep_dive_1_scene2`)/ `segment_type` / `prompt`(FLUX に渡した全文)/ `visual_identity` / `seed` / `generation_time_sec` / `resolution` / `steps` / `sampler` / `cfg_scale`
  - 今回足した欄:
    - `scene_visual`: 台本の指定(`start_turn` / `focus` / `draw` / `avoid`)。scene_splitter で切った場面では null
    - `cached`: キャッシュの絵を使ったら true。013 より前は、キャッシュを使った場面は記録が残りませんでした
- **md**: 各項に `Scene source`(`visuals (start_turn N)` か `scene_splitter`)/ `Focus` / `Draw` / `Avoid` / `Cached` を足しました
- `image_path` は `output/.image_cache/<hash>.png` です(本番ツリーからの相対パス)。絵そのものを Mac に取り寄せるなら、本番ツリーの直下を基準にしてください
